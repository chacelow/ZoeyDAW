# gpuix UI 规范

2026-10-14。适用于 `apps/gpuix` 里所有可见界面。本文是[视觉验收](gpuix.md)的检查清单：每条都能在真实窗口里用截图或 AX bounds 核对，不接受「看起来差不多」。已有产品决策不在此重复，冲突时以 [gpuix.md](gpuix.md) 与 [project-panels.md](project-panels.md) 为准。

## 1. 工作站的紧凑感

- 这是 DAW，信息密度高。每个像素都要有用途：不用网页卡片式的大圆角、大内边距、整块留白。
- 同一区域与 Ableton Live 并排截图比较：控件行高、内边距、文字大小应在同一量级。明显更松就是缺陷，不是风格。
- 层级靠颜色与细线表达，不靠额外间距。分隔用 1 条细线或背景色差，不叠加「线 + 间距 + 阴影」。
- 默认控件尺寸取 `CONTROL_METRICS.default` 的紧凑档；`transport` 档只用于走带区。不在单个实例里临时放大或缩小。

## 2. 尺寸与间距

- 所有尺寸、间距、图标大小来自 `CONTROL_METRICS` / `PROJECT_METRICS` 或主题 token；组件里不出现裸像素字面量（0、1 的描边宽度除外）。需要新值，先加 token，再引用。
- 同类位置同一值：标题与内容的间距、控件之间的 gap、面板内边距各取同一个 token；不要「这里 6、那里 8」。
- 同组控件等高。纯图标控件是正方形，不因文字留白被拉宽。
- 数值控件宽度按**实际格式化字符串的测量宽度**定，取该控件可能出现的最宽值（含小数、负号、三位整数），并**保持稳定**：内容变化、进入预编辑或编辑态都不改变宽度、字号或隐藏图标。测量接口见架构文档的渲染器决策；在原生测量可用之前用字符宽度估算，并在报告写明。
- 面板边框、分隔条、内容区的内边距按「组件内部拥有自己的内边距」处理，不靠外层 margin 补；Header 与其下方面板的间距属于组件内部。

## 3. 对齐与居中

- 数值、文字、图标在控件内水平与垂直居中；数值控件内容居中显示。
- 图标与文字基线对齐；图标与文字之间留紧凑但非零的间距，不贴死也不松散。
- 列表项文字左对齐并统一内边距；右侧指示器（下拉箭头、状态点）固定在右边缘，与文字之间留出间距，不重叠。
- 文字过长时省略并保持单行高度；允许换行的列表项（下拉列表）保留原有换行，不强制单行。
- 相邻元素的边框不出现双线、缺口或 1px 错位。需要时让外层容器持有边框，内部不再各画一条。

## 4. 排版

- 字体、字号、行高取主题；不在组件里写死字体名。数字用等宽或表格数字，防止拖动数值时抖动。
- 弱化文字（标题、次要信息）用主题的 muted 色，不为强调而提亮；强调靠状态而非字号。
- 中英文切换后，控件宽度、截断与对齐都要复核；验收中英文各一遍。

## 5. 颜色与层级

- 颜色只经 `useTheme()`；不 import `colors.ts`，不写十六进制字面量。轨道、Clip 的用户内容色来自工程文档，不是主题色。
- 同一表面：Header、标题栏、Panel 的背景色相同，之间没有间隙、边框、卡片感或分隔线。
- 网格线与分隔线：用共享的深灰档，可见但不是最亮元素，也不暗到看不见。粗细网格线要有明确的视觉差别。
- 深色与浅色主题都要验收；不得只在深色下看。
- 遮罩、压暗（如标题栏覆盖层、Mapping On 遮罩）用半透明叠层表达，不直接改按钮自身颜色或边框。

## 6. 状态

每个交互控件逐一核对并截图：默认、悬停、按下、聚焦、禁用、激活（selected/pressed）。

- **高亮独立于 hover**：交互组件有自己的高亮态，默认开启，并提供关闭它的变体。悬停高亮整个组件，不是只出现一圈边框。
- 状态必须彼此可区分；禁用态不可被误认为默认态。
- 激活态由控件状态驱动（`selected`、`pressed`），共享 hover 规则不得覆盖它。
- 数值控件：预编辑态有高亮和插入符；输入后实时编辑数值；双击重置；图标在预编辑与编辑态都保持可见，不靠换背景色区分。

## 7. 指针、拖动与滚轮

- 拖动调整数值：隐藏光标并锁定起点，按相对位移调整，松手把光标放回按下点，且松手瞬间不出现光标跳变。使用 `@zoeydaw/native` 的原生光标能力，不在 JS 里模拟锁定。
- 垂直步进只取决于指针位移与步长，不加阻尼、不看速度。
- 同一组件族共用同一套拖动比例，包括小数值范围；不为某个组件另起一套灵敏度。
- 悬停可调控件时，滚轮可调整数值，且不隐藏光标；已被控件消费的滚轮不再滚动外层容器。
- 拖动 Pattern 或 Clip 时保持拖动光标，悬停文字不得变成文本选择光标。
- 时间线使用默认箭头，不用十字光标；不因单独按下 Ctrl 产生无法解释的指针变化。
- 拖动中遇到失焦或应用失活：取消并回滚到拖动前状态，光标恢复显示。

## 8. 弹层与列表

- 弹层可向左、右、上、下对齐触发器，不强制触发器宽度、不强制向下打开。
- 含可调控件的弹层，在内部点击、调整与释放期间保持打开；只在用户离开或主动关闭时收起。
- 下拉指示器固定在右边缘；列表项保留换行；所有列表（下拉、Browser）共用同一套项高、容器与卡片样式。
- 筛选控件：激活指示与文字之间留间隙。
- 弹层关闭后焦点回到触发器；Esc 关闭。

## 9. 键盘与焦点

- Space 只控制播放：不得激活已聚焦或刚点过的按钮，也不触发该按钮的按下样式。
- 窗口级快捷键走窗口根键盘事件，不用 JS 定时器轮询。输入框与可编辑控件聚焦时，快捷键不得吞掉文字输入。
- 所有可点击元素可经 Tab 到达，焦点环可见；焦点顺序与视觉顺序一致。
- 单键切换（如 M 切换轨道编辑模式）再按一次必须还原。
- 快捷键与命令名以 Ableton Live 菜单的实测为准（只读读取菜单），不凭文字描述：`Cmd/Ctrl+1` 缩窄网格、`+2` 加宽网格、`+3` 三连音网格、`+4` 吸附到网格、`+5` 固定网格、`+E` 裁剪（Split）。

## 10. 可访问性与语义

- 每个可交互元素有可读的名称与角色；AX 树里能看到它们，这也是自动验收的入口。
- 切换类控件暴露选中状态；禁用控件暴露禁用状态；数值控件暴露当前值。
- 纯图标按钮必须有文字标签（用于 AX 与 tooltip），不得只有图标。
- 动画可被减弱：尊重 reduced-motion。

## 11. 动效

- 动效短且有因果：状态变化、展开收起、拖动预览。不做装饰性循环动画，播放中的节拍器除外（每拍摆动一次，交替填充侧）。
- 窗口宽度、面板宽度连续变化时用连续过渡，不瞬时切换；折叠侧栏时子列表保持固定宽度，不一起缩。
- Mapping On 的闪烁从零亮度升到满亮度，不反向。

## 12. 性能与渲染

- 时间线、轨道、Clip 用原生元素加**可见范围裁剪**；屏外元素不挂载。滚动与缩放不重建每个 Clip 的节点。
- 绘制与重排以帧为单位合并；用 `getDebugFrameOverlayStats` 报告帧数与耗时，不用 JS 定时器数量冒充帧数。
- 手势预览不是第二份工程数据，不写入快照；提交前不改工程。
- 滚动时 minimap 固定，轨道表头与其 Pattern 卡片作为整体一起滚动；共用一条横向滚动条。

## 13. 验收清单（每个界面切片交付时逐条回答）

| 检查                               | 证据                             |
| ---------------------------------- | -------------------------------- |
| 每个控件每个状态各一张放大截图     | `evidence/` 下文件名含控件与状态 |
| 间距：同类位置同一 token           | 量出的像素值与 token 值对照表    |
| 居中：文字、数值、图标             | 放大截图与 AX bounds             |
| 尺寸：同组等高，图标控件为正方形   | AX bounds                        |
| 紧凑感：与 Live 同区域并排         | 并排截图与差异说明               |
| 深色与浅色、中文与英文各一遍       | 截图                             |
| 键盘：Tab 到达、焦点环、Space 行为 | 操作记录或 AX                    |
| 动态交互：拖动、滚轮、弹层保持打开 | 操作前后 AX 值                   |
| 性能：可见范围裁剪生效             | 帧数/耗时与挂载节点数            |

没有证据的条目一律按「未验证」处理，切片不合并。
