# 工程流程对比：Zed 与 ZoeyDAW

## 范围与结论

只读比较当前仓库与 `.gpuix-main/zed` 的 vendored 代码，没有构建、运行测试或启动应用。下文的 Zed 路径均保留 `.gpuix-main/zed/` 前缀。代价为工程判断，不是测量工期；速度、费用改善均为 `[INFERENCE]`，没有两边 CI 耗时和账单，不能声称 Zed 实际更快或更便宜。

最值得学的是让测试环境、异步完成条件、Rust 质量门禁和配置失败处理成为可执行契约。我们的优势是已有真实 native UI 测试、变异检查和统一验收入口，不需要换掉 `bun:test` 或把应用重写成 Rust。`createTestRoot` 目前通过 React reconciler 创建 native TestRenderer，不是 Rust `TestAppContext` 的直接入口，见 `.gpuix-main/packages/react/src/testing.ts:20-39`。

任务提供的“首批 hosted CI 失败，窗口被夹到 1024”按已报告事实处理，没有重新运行确认。代码证据能确认尺寸假设和诊断入口，不能仅凭这些代码证明夹取发生在哪一层。

- **真实 native UI 测试已有良好起点。** React root 经真实 native renderer flush；Header 测试覆盖宽窄尺寸、不同字体与首次挂载。`.gpuix-main/packages/react/src/testing.ts:20-39`、`apps/gpuix/src/project/sections/transport/index.test.tsx:266-292`。Zed 也要求 UI visual regression 和截图，`.gpuix-main/zed/CONTRIBUTING.md:62-64`。不能把我们的 `bun:test` 误当成只有 JS mock。

## 不适用于我们

- **不能直接从 TS 调用 Rust GPUI 测试 API。** Zed `TestAppContext` 直接持有 Rust App、executor 和 TestPlatform，`.gpuix-main/zed/crates/gpui/src/app/test_context.rs:18-34,123-145`。我们的 React 桥只暴露 root/native TestRenderer，`.gpuix-main/packages/react/src/testing.ts:13-39`。可迁移的是控制时钟、任务与事件完成条件，完整 executor 随机化需 renderer/native 桥支持，不是给 Bun 加一个 `SEED` 就完成。
- **不照搬全平台重型 CI。** Zed Windows、Linux、macOS 的 clippy/test jobs 是多平台产品的覆盖选择，`.gpuix-main/zed/.github/workflows/run_tests.yml:189-217,219-263,357-358,418-419,473-474`。我们当前 gate 明确 macOS native，`.github/workflows/ci.yml:15-23`。先覆盖自有 Rust 与实际发布平台；没有当前平台验收目标就不扩展矩阵。
- **当前 pinned workflow 没有可证实的通用测试分片矩阵。** 这里看见的是按平台拆 job、按 `rdeps` 过滤和 nextest 测试组，`.gpuix-main/zed/.github/workflows/run_tests.yml:105-113,357-358,418-419,473-474`、`.gpuix-main/zed/.config/nextest.toml:1-22`。搜索 workflows 没找到 `--partition`；不能把其他 extension workflow 的 matrix 当成主测试分片。我们单 job 的问题应按证据讨论，而不是按印象夸 Zed。
- **不要照搬编辑器的用户/项目/语言配置继承。** Zed 有 user/global/local settings 与不同 user/project schema，`.gpuix-main/zed/crates/settings/src/settings_store.rs:146-160,1318-1327`。我们目前是四项用户 UI 偏好，`crates/native/src/settings.rs:42-53`。项目设置应跟工程数据 owner 分清，不把主题、设备偏好和工程可复现参数自动混成层层覆盖。可借鉴边界和默认值契约，不需要它的全部继承层级。
- **不把文本设置编辑器和自动遥测上传当必需品。** Zed 通知跳转设置文件，`.gpuix-main/zed/crates/zed/src/zed.rs:2016-2028`；我们是图形设置 dialog，`apps/gpuix/src/app/settings/SettingsDialog.tsx:106-156`。应该迁移“失败可见且可恢复”，不是要求 DAW 用户读 JSON。Zed crash init 带 session 身份，`.gpuix-main/zed/crates/zed/src/main.rs:396-400`，我们已有脱敏 logger，`apps/gpuix/src/platform/log/logger.ts:168-188`。先做本地诊断导出；音频工程和路径可能敏感，远程采集另定授权政策。
