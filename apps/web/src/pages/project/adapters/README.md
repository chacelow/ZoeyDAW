# Project state adapter

`index.ts` is the UI's project data interface. `useProjectState(selector)` reads the composed Zustand root; `projectActions` issues synchronous, optimistic domain commands. `document` contains authored project data, `workspace` contains view geometry and editor preferences, and `session` contains playback, selection, backend status and undo availability. MeterStore owns all meter samples outside the project state tree.

## Backend registration and lifecycle

`@zoeydaw/project-core/backend` defines the engine port and DTOs. `@zoeydaw/project-runtime` exports `createProjectRuntime({ store, backendFactory, defaultTrackHeight, createProject? })`. The store supplies `getState`, `setState` and `subscribe`; separate stores produce separate editing/resource owners. Construction and public module import do not open a backend. `context.ts` composes the current single-project instance with the native backend and app layout height.

`configureProjectBackend(factory, options?)` installs an implementation and returns an idempotent cleanup. Registrations form a stack; removing an older registration does not replace the active one. While idle, registration and hydration only update data/configuration. With an acquired runtime they replace the connection, cancelling temporary edits and preserving the committed document. A factory creates a fresh backend for each engine session.

`options.createProject(projectId)` returns a synchronous `ProjectSeed` containing `document` and `workspace` for a new route. Without that callback an external registration starts with one empty Audio track routed to Main, using standard track defaults, and no demo content. The built-in mock registration supplies demo tracks and media. Reset, hydration and replacement normalize a seed with no Audio/MIDI track before opening the backend; existing authored data is preserved. Switching registrations does not silently discard an already-open project. Load parsed project data with `hydrateProject(json)` after any asynchronous file read.

`setProjectStorageId(projectId)` changes editing ownership on route entry; it does not load a file. The project view explicitly acquires `startProjectRuntime()`. First acquisition opens/subscribes; the last release cancels unfinished edits, retains independent authored recording, stops playback and disposes the backend. Idle authored edits and undo do not acquire an engine. File saving explicitly holds a runtime lease while waiting for the captured revision.

`session.editEpoch` is a subscribable editing identity independent of engine `sessionId`. Tokens, controls and Canvas use it while live or idle; hydration/open/release invalidate old ownership. Engine acknowledgements and telemetry retain their protocol/session fences. `packages/project-runtime/src/runtime/` owns the coordinator; its internal `backend/connection/` owns protocol validation, queueing and interpolation. Mock backends and fixtures are available only through the explicit `@zoeydaw/project-runtime/testing` entry.

`context.ts` installs `createNativeProjectBackend()` for production. It rejects playback outside Tauri instead of falling back to a simulated clock. `createMockProjectBackend()` remains an explicitly injected test and Gallery provider; it produces no audio. Demo `mock://` references are fixtures only. Newly created audio clips have no source, not a fabricated file reference.

## Commands, confirmation and recovery

`ProjectBackend` separates `apply(BackendDocumentRequest)`, `control(BackendControlRequest)`, and `launch(BackendLaunchRequest)`. All use protocol version 2, session identity, dispatch-time safe-integer sequence and decimal-u64 `controlGeneration`. Only document requests contain project, revision/baseRevision, stage and edit ID. The connection keeps one document, control or launch request in flight. One latest control can jump ahead, then a queued document or launch runs before another control. Document and launch dispatch use the latest control. Preview coalescing cannot cross a launch command.

Live MIDI uses ordered `note` edges with trackId, noteId, pitch, velocity and on/off, not held-note control snapshots. Pitch and velocity use 0–127. Notes have an independent sequence starting at 1 and bounded pending capacity 4096. `allNotesOff()` releases notes without stopping arrangement or changing history; its native cutoff rejects previously dispatched note sequences even if they arrive after panic. Future requestedSample scheduling is explicitly rejected by the current native path rather than silently played immediately.

Native providers expose `urgentStop()` independently of document/control dispatch. The adapter admits a lease/session through `playback_acquire` before requests, captures stop tokens at submission, and waits for the corresponding Stop acknowledgement before dispatching newer requests. Stop fences survive Stop→Play coalescing. An open cancelled locally before native submission returns `superseded-open`; only that explicit case is reopened with the next sequence and latest control, preserving queued document transactions. Ordinary failures are not retried. Native pending/active ownership authorization prevents another lease from muting the current project.

Session scenes and quantization belong to `document.launcher`. Each track owns sparse `clipSlots` keyed by scene ID. Slot content has its own global Clip ID and no `startBar`; copied MIDI notes are independent, while Pattern references retain shared `document.patterns` content. Scene order determines native slot indexes. Removing a scene removes its slots without changing Arrangement clips. Names, colors, order, content and quantization use the existing document history and save path.

`launcherActions` exposes scene edits, slot copy/move/delete, MIDI slot creation, launches, per-track stops, Stop All and Back to Arrangement. Selecting an occupied slot opens the existing Clip editor. Clip lookup, names, audio parameters and piano-roll edits use the same content identity across both placements. The Session toggle is inside the Arrangement panel; hiding it does not stop playback or create another backend.

Native launch requests use the existing `playback_control` IPC and do not advance document revision. Tracktion `SceneList`, `ClipSlot` and `LaunchHandle` own scheduling. Commands queued behind documents stay ordered; Stop removes waiting launches and retains the native stop fence. Quantization uses one SDK monotonic sync point for all tracks in a scene. Unwarped slot audio uses explicit rate-only processing with matching tempo metadata rather than the SDK's implicit default stretcher.

`session.launcher` contains read-only observations from the existing status poll. Playing and queued states come from `LaunchHandle`, not command acceptance or a Web timer. Retired connections cannot write into a replacement session. Native source selection follows the audio handle immediately rather than waiting for the SDK's message-thread mode mirror. Slot fades and playback markers use launch-local beats and rendered source duration. This does not add Session recording, follow-action editing or a complete document audio-adoption revision.

Auto input monitoring excludes unlaunched slot content from Arrangement time ranges. The existing InputMonitorNode retains SDK track/handle references and gates input at queued launch/stop sample boundaries. A playing slot suppresses monitored input, a stopped slot restores it, and a return to Arrangement restores its authored ranges. In, Off, stopped transport and recording retain their existing behavior. Hosted PCM checks this path without physical input hardware.

| Stage     | Applied state                                         | Durable revision       |
| --------- | ----------------------------------------------------- | ---------------------- |
| `open`    | Initial project and transport control                 | Starts at zero         |
| `preview` | Temporary effective project                           | Unchanged              |
| `commit`  | Authored edit, undo or redo                           | Advances on acceptance |
| `cancel`  | Project without the temporary edit                    | Unchanged              |
| `recover` | Last accepted project plus retained independent edits | Advances on acceptance |

`control` handles Play, Stop, recording intent and seek without project projection, media resolution or waveform warming; it does not advance document revision. Starting recording also starts playback. Stopping playback ends recording; disabling recording alone preserves playback. MIDI injection uses an application-owned front-chain Plugin and existing JUCE AbstractFifo. The upstream PluginNode MIDI buffer may allocate; bounded input does not establish a zero-allocation whole callback.

An accepted result echoes the session and sequence and reports the accepted document revision after native model updates return. It does not confirm that a rebuilt playback graph or a complete parameter batch has reached an audio block. A protocol rejection before mutation leaves the accepted state intact; arbitrary native setter, graph preparation or rollback exceptions do not yet have a proven failure-atomic guarantee. Promise rejection or a thrown `apply` becomes a connection failure; malformed or mismatched results become protocol failures. There is no automatic timeout or generic retry policy.

On failure the runtime drops queued dependent edits, restores the accepted document and history, preserves current viewport/preferences and independent recording edits, and sends a recovery state. `session.backend` exposes phase, pending count, accepted revision and error; the Arrangement toolbar displays pending/error feedback. Successful recovery permits saving again while retaining the error indication until a later commit succeeds. `whenProjectBackendIdle()` waits for the current session's queue to settle and returns false for an unrecovered failure or disposed session.

Native audio recording uses configured, armed audio inputs and Tracktion's recording writer. Starting from stopped transport releases its old playback context before binding inputs, so a pending backward or forward seek cannot insert a timeline-sized silence prefix into each writer. Punch-in while playing retains the active context. Each armed target owns a take file and stable Clip ID, including targets sharing one physical input. Writer-fed thumbnails publish bounded signed extrema and growing durations through the same telemetry snapshot. Closed files remain outside the authored document until inspection and `recordDocumentConfirmed` publish their media identities and clip placements. Recorded clips start with warp and loop disabled. The runtime journals recording edits independently of active previews and returns a receipt only after backend acceptance in the same project epoch.

Recording previews use the same Clip geometry and card painter as committed audio, with signed writer-thumbnail waveform data. While recording, a translucent destructive-color overlay covers each recording track and its header. The preview remains until the committed source waveform takes over; stopping removes the track overlay.

`recording_ack` retires result metadata only after a matching publication revision has been accepted. It never deletes audio files. ACK retries reuse the accepted receipt without reinserting clips, including after a later user deletion. Writer failure and queue overflow retain recovery files and report an error rather than publishing an incomplete take. Hosted input tests verify exact PCM, publication and ACK ownership; physical microphone capture and desktop interaction are not yet verified.

Failed takes are excluded from `recording_results` without being consumed. They remain outside the authored document and reject ACK until explicitly recovered and validated. The same owner's telemetry includes a `recording-failed` issue with the take ID and original error, while complete takes continue through inspection, document publication and ACK. Other leases do not receive those errors.

Each take directory contains a bounded version-1 `take.json` journal. The native owner writes a flushed temporary file and replaces the journal before recording starts, when files are allocated and when recording finishes. States are `recording`, `complete`, `failed` and `published`. The journal retains stable file/Clip IDs, source BPM, seconds per bar, initial targets and exact finalized placements. ACK retires the in-memory result but marks the journal published rather than removing it, because backend acceptance is not a project save. Original audio and published journals are retained; this feature does not automatically prune recordings or guarantee recovery after sudden power loss.

File → Recover Recordings lists disk journals only on request. Recovery explicitly targets the current project and creates isolated, unarmed Audio tracks with monitoring off, never silently matches an old session to a new project. Native verifies lease/session ownership, file identities, directory containment, readable dimensions and source bounds. Interrupted journals use measured file duration and persisted targets. Recovery converts duration and source offset to the destination timebase without enabling Warp. Unreadable files remain on disk and return an error; no repair or invented PCM is substituted.

The current native backend owns the single recovery request and suppresses competing result polls. It waits for the normal recording publication receipt and ACK before reporting success. Repeated reclaim preserves identities; existing media prevents duplicate insertion or resurrection after deletion. Window/project changes fence late replies. The dialog owns only list/error/loading state and uses shared Dialog/Button controls. Browser explicit-mock rendering and native disk/PCM tests remain separate from Tauri desktop and physical microphone acceptance.

The engine DTO excludes names, colors, view geometry, waveform caches and PCM buffers. It includes timing, routing, mixing, automation, source windows, MIDI/Pattern content and fade metadata. `BackendAudioClip.sourceId === null` denotes an empty, silent clip. Other source IDs refer to stable identities in `document.media`; `project.sources` includes their effective paths, SHA-256, frames, sample rate and channels. Audio settings retain fixed source BPM, warp, reverse, transpose, markers and loop coordinates. Musical coordinates are one-based bars; MIDI beats use the document meter-beat convention. Native processing reports unsupported capabilities as issues rather than claiming parity with Live's warp modes.

## Editing and rendering

Canvas gestures use `beginPreview()`, `previewTracks()` / `previewMarkers()` / `previewLoop()`, then `commitPreview()` or `cancelPreview()`. The runtime owns the effective edit and backend stream. `getEffectiveDocument()` projects the current temporary state; Canvas Scene consumes that projection rather than owning a second editable document. Shared Clip move/resize and automation projections keep preview and commit placement identical.

Continuous controls use `useProjectEditGesture(onChange)`, which owns a session-scoped token and guards value updates as well as `beginEdit`, `endEdit` and `cancelEdit`. Rejected or stale gestures cannot turn later pointer movement into unowned commits. A stale component cleanup cannot commit or cancel another control's edit. A completed gesture creates one undo entry; cancellation restores authored values without resetting viewport movement. Explicit workspace toggles are undoable, but pan/zoom/scroll, playback, selection and edit focus are not. Undo/redo uses the same backend commit path and preserves a surviving Clip editor.

External Device automation targets use the exact decimal-u64 IDs declared in `device.parameters`. Values remain normalized to 0–1, displayed as percentages; SDK adapters handle native discrete quantization. Unknown IDs are rejected at snapshot and native document boundaries. `usePluginParameters` loads native names and flags for the current editing epoch, backend session, Device, catalog and state hash; disposed requests cannot replace another owner's metadata. Without metadata the selector shows the declared ID, not an invented parameter name.

Authored automation points and the shared backend model remain normalized to 0–1. The native backend converts each point once with `automationSourceValue` immediately before `port.apply`, alongside source and plugin location resolution. Native mixer and built-in Device curves therefore receive dB, pan, Hz or the corresponding declared parameter units. External plugin curves retain normalized values. The adapter copies lanes and points; serialization, Undo, Gallery and mock playback never receive the converted native units.

The isolated wrapper registers Tracktion parameters and keeps an atomic authored-curve bitmap, including single-point curves that Tracktion optimizes out of active streams. Its graph node evaluates the existing parameter streams at the SDK's fine-grain interval with graph-latency compensation. Events use slot zero of the single-plugin processor and offsets within the current graph block. Unchanged values within a block are omitted; offset-zero values are replayed each block so endpoint recovery does not retain a manual value over an envelope. Combined MIDI and automation remain bounded to 4096 events. Manual updates use remaining capacity across blocks; curve overflow faults rather than dropping events silently.

While an authored curve exists, editor notification and commit values do not overwrite that parameter's authored manual baseline. Removing the curve restores that baseline. Ordinary value and envelope edits retain the Edit and prepared plugin; changing the declared parameter schema requires preparation.

Transport Read/Touch/Latch is session state, initially Read. Mixer volume/pan and built-in/external Device controls use `useAutomationGesture`; recording starts on the first value change while playback has an accepted, recent backend position. Read and stopped gestures retain ordinary manual editing. Touch restores the original envelope at release; Latch holds the last value after release until Stop, seek, save, mode change or another edit. A backward jump ends the take at its previous observed position. This does not automatically rearm after loop wrap.

`runtime/automation-recording.ts` owns one active take and publishes through the existing editing token and backend FIFO. Manual baselines remain unchanged. Cancel restores the prior document; a completed take is one undo entry. Curved segments outside the overwrite retain their evaluated shape. Recording uses raw accepted telemetry, never the interpolated display clock; observations older than 250 ms cannot start a take. Synchronous preview responses update the clock without recursively recording their own publication. Timing remains bounded by Web input, telemetry and document dispatch; sample-accurate gestures, simultaneous independent takes and plugin-editor gesture capture are not claimed.

Song Tempo is a Main-only mixer automation target in the existing normalized envelope model. Main automation points remain the only authored tempo-map owner and use the existing snapshot and history. `projectTempoSections` derives ordered bar/BPM sections for the backend and time projections; without points the constant `transport.bpm` path remains. With a tempo envelope, the Transport BPM displays the mapped position value and is read-only; TAP is disabled. Edit the Main envelope or remove its points to return to manual tempo.

Tempo ramps use one step per sixteenth note, capped at 100 steps per point interval and 65,536 sections per map. These are piecewise-constant approximations, not continuous native curves. Native reuses Tracktion TempoSequence and retains Edit for tempo-only updates. Bar/time inversion, loop/seek, Clip lengths, original-speed source coordinates and recording duration use the same sections. Hosted rendering and exact recorded PCM are verified separately from Tauri gestures and physical click-free listening.

## Telemetry and native integration

Production meters and transport share MeterSession and one window-bound binary stream. The native backend opens it after its project is accepted, including stopped projects without a graph, and closes it before releasing the audio lease. `native-transport.ts` owns frame subscription, transport interest, visibility and disposal through NativeTransport. `shared/native/realtime.ts` validates registry and ordered Channel batches; frames remain raw ArrayBuffer. Track, routing and Device meters read the same MeterStore. Explicit Gallery mocks produce fixture frames and no audio.

Registry refresh uses the backend status poll at most every 250ms to discover graph changes. First Play also refreshes when the latest transport has no audio graph. High-rate binary reads never dispatch to main. Transport comes exclusively from Hub frames; device status and recording thumbnails retain the status query. WebView interaction and throughput remain unverified.

An unprepared registry has no graph endpoints and remains admitted. It can contain independently playing Preview sources. The same binary stream reports Stopped or Unavailable while the Arrangement sample clock probe returns null. A prepared graph advances metadata generation and resumes Audio observations on that stream. Registry and interest changes discard pending or late responses, with one snapshot invoke in flight. Identity and protocol failures remain errors.

Source observations pair the position written by WaveNode or WaveNodeRealTime with that process call's reference sample and sample rate. Graph-specific playheads prevent retired or candidate graphs from overwriting the current source bank. Arrangement uses the transport reference/device anchor. The Preview graph root publishes its own processing reference paired with the existing device counter, so Preview source positions remain available before Arrangement has a graph. observedDeviceSample is the source processing sample, and positionAgeSamples is its age relative to that graph's anchor. Future blocks, format mismatches, counter underflow and samples older than 50ms remain unavailable.

Audio Editor and Browser use `readProjectSource` and `watchProjectSources` through the existing MeterStore. Arrangement selectors require Clip and source IDs; Preview selectors require its reserved generation's Clip ID. SourcePlayhead and SourceTimeReadout use the shared scheduler and DOM projection without per-frame React state or timeline extrapolation. Unknown, stale, mismatched and out-of-view positions hide the line; unknown time displays a dash. Browser status polling runs every 250ms for completion and errors and carries no position into UI state. Native audition diagnostics retain their control-position query for audio smoke tests. Desktop presentation remains unverified.

`playback_clock_probe(streamId)` is window-bound and uses the same Rust Hub monotonic origin as binary `producedMonotonicNs`. After the first frame, MeterSession collects five serial samples every five seconds, keeps the smallest RTT midpoint and half-RTT uncertainty, and exposes `readFrameAge()`. Visibility changes discard the mapping. This measures Hub publication age, not the full audio-block-to-paint latency; actual WKWebView percentiles remain unmeasured.

Endpoint and transport interests are independent. A transport-only subscriber keeps the shared scheduler active with zero meter slots; with neither interest it sleeps. Interest revisions invalidate pending and in-flight responses without creating a second invoke. NativeTransport removes frame and interest subscriptions before MeterSession disposal, then closes the stream before lease release. Meter consumers rebind on backend replacement and report actual paint costs to the shared pull budget.

The project meter scheduler normally ticks on animation frames. If frames stall, a 100 ms watchdog ticks the same MeterSession until frames resume; it stops when the stream is hidden, idle, failed or detached. This preserves the existing single-flight pull and real native clock instead of repeatedly discarding every response after a long frame gap.

`subscribe(listener)` retains the BackendTelemetry contract consumed by connection validation, Follow and playhead projection. NativeTransport forwards the frame's valid control identity, uses same-block audible coordinates while playing, and uses a musical clock for a no-graph stopped position. Binary u64 counters remain exact in MeterStore; the adapter assigns a bounded local receipt sequence for the existing numeric backend interface. Repeated Hub publications of the same audio observation do not refresh the clock. Pending or unavailable identities cannot acknowledge a new seek or control generation.

Transport frames and recording-result fetches progress independently. The connection retains acknowledgement buffering, its 250ms interpolation limit, loop wrapping and BPM handoff correction. Seek/control generation changes, stops and actual loop wraps bypass correction. Raw Hub coordinates remain unchanged; neither this projection nor Hub reception time establishes physical presentation time.

A provider can report a musical clock or a sample clock with frame and sample rate. Native adapters parse IPC at their boundary. The provider owns realtime processing, decoding, media resolution and cancellation/disposal. Audio callbacks never publish PCM or invoke WebView work. Canvas `audio/project-telemetry.ts` updates only the small local playhead projection; meter consumers read MeterStore directly.

The explicitly injected mock provider retains simulated MIDI monitoring and recording tests. Native audio recording uses Tracktion input writers. Instrument-less MIDI remains silent. File storage remains independent of the playback engine. `shared/native/audio.ts` parses device, telemetry and result payloads at the IPC boundary; the project adapter supplies authored state and owns its lease.

Audio settings use one native configuration owner. `playback_device_capabilities` probes a host and input/output pair without opening audio. Each valid user selection configures the device immediately after capability fitting. Opening or refreshing settings only reads the current configuration. Native operations are serialized, stale capabilities cannot replace newer choices, and unmounted views cannot publish late replies. `playback_configure_device` accepts the complete host, independent device IDs, sample rate, buffer size, and zero-based mono/stereo selections. The native owner rejects unsupported values and silent driver substitutions, restores the prior device and transport state on failure, and atomically persists successful configurations. Actual state changes only after acknowledgement.

Audio settings display an acknowledged device configuration and matching capabilities as soon as the snapshot is available, including when it arrives after the page opens. Device discovery and capability refresh continue asynchronously; opening the page does not apply a configuration.

Explicit sample-rate and buffer changes first query `configuration_plan`. When current processors already match the requested format, configuration keeps them. Otherwise `plugin_devices/configuration.rs` captures each live full state on the existing control worker, prepares a new processor and reapplies declared manual parameters before native configuration starts. Apply, configuration and explicit recovery share one async update guard so native acceptance and the registry update cannot interleave. This does not create another document Store or audio backend.

Native rechecks the lease, document revision and sequence, previous configuration and callback contexts before consuming the prepared batch. It frees the stopped playback context, installs new wrappers and uses the existing driver and preference rollback. Failure restores old wrappers with the old configuration. Successful changes keep the Edit and authored document and publish controls only after native success. An editor that still owns parameters blocks incompatible configuration rather than losing or committing its transaction. Failed captures, changed parameter schemas and stale plans return real errors without retry.

Driver-panel and system-originated format changes use `device_recovery_plan` from the same backend status observation. `EngineSession` reads the open device and prepares an observed configuration only when an external processor has an incompatible format. `PluginDevices` uses the existing update permit and full-state worker, then native checks the device generation as well as the document and processor owners. A device that changes away and back invalidates the old plan. Adoption refreshes routes, graph latency and acknowledged runtime configuration without reopening the driver, requesting input permission or overwriting audio preferences.

An incompatible isolated node emits silence and all-notes-off until it has a compatible graph; it does not invoke the old processor or leak dry audio through bypass. Closed devices remain unavailable. Failed preparation retains the previous instance and reports the real error through the device snapshot and issues. An unchanged failed plan is not retried on every status poll; a new plan or successful explicit configuration clears that failure. Lease and window release discard their failure entries. An open editor blocks recovery until its transaction is applied or closed.

`usePluginParameters` includes observed sample rate and buffer frames in its metadata identity. Format notifications use the existing low-rate audio status subscription. Late old-format responses cannot replace current names or flags. Hosted CLAP/VST3 probes cover format safety, full-state PCM, automation, refreshed latency and device-generation rejection. Physical driver changes and Tauri interactions remain separate acceptance checks.

`AudioDeviceSnapshot` separates the last acknowledged configuration from active device rate, buffer, input/output channel counts and driver-reported latency frames. Closed devices have no active latency reading. Overall latency is the reported input plus output latency, not a loopback measurement. Track routing uses enabled mono/stereo selections. Selecting an input enables its capture channels after OS permission; it does not arm tracks or turn monitoring on. Browser Preview retains its independent output path. The settings preserve theme and language controls. Sample-rate conversion quality, driver error compensation, test tone and CPU simulation controls from the reference are not implemented.

Legacy external-audio tracks with no `inputChannel` use the same mono `1` default in the display and backend projection. Selecting External Input on a track without a channel persists an enabled device-channel choice. Explicit channel selections are retained, including unavailable channels that must be corrected rather than silently remapped. Native failures retain their original message in the Arrangement error feedback.

Tracktion custom wave-device descriptions are generated from the same acknowledged mono/stereo configuration used by the selectors. The custom description path overrides XML layout state, so it replaces the description list rather than appending defaults. Stopped project open restores an existing saved input configuration without requesting new permission or starting playback. Permission/device failures keep the project open and report the original device error; live capture from a cold desktop start requires separate physical validation.

`adapters/browser/` owns registered-root navigation, folder expansion, virtual tree windows, query and audition generations. `crates/browser` persists directories, including empty folders, and audio leaves in a version-2 index. `browser_tree` projects a folders-first visible preorder slice on a worker; the UI virtualizes that slice without exposing pagination. Search retains matching ancestors. Removing a root never deletes its media. Added folders and the final Add Folder control live in left navigation.

Browser audition always uses original speed and pitch through an independent Preview Edit connected directly to the output, bypassing the project Master chain. Its autoplay switch affects selection only; the selected audio waveform remains visible while stopped. Clicking the waveform seeks and starts playback even with autoplay disabled. Generation-fenced native status polling supplies the actual source-time playhead; a late poll cannot overwrite a new selection or seek. Generic engine sync audition remains an engine capability, not a Browser control.

While Browser audition is preparing or playing, Space interrupts and resets that audition without toggling Arrangement transport. A pointer press inside Arrangement also interrupts/reset audition while allowing the editing gesture to continue. Reselecting the same Browser audio starts from zero; text entry and IME retain native Space behavior. The same audition generation fence rejects late select/poll results after interruption.

Playing preview status reads `EditPlaybackContext::getPendingPositionChange()` or its live `getPosition()`; `TransportControl::getPosition()` is only used while stopped because its UI cache pauses updates for 200ms after positioning. A superseded generation is silenced by the audio fence immediately, then stopped on the message thread without clearing the still-fenced graph. This preserves valid stopped state and actual silent capture samples; no timer-generated playback position is used.

Audio Clip content can carry `sourceTempo: "unknown"`. New imports with no accepted tempo, including Auto-Warp-off imports that skip analysis, retain this marker. The numeric `audioSettings.sourceBpm` remains the fixed coordinate basis for source seconds and markers, not a claimed detection. The editor displays Unknown and disables Warp until the user assigns a source BPM through the existing numeric control. Manual assignment clears the marker in the same undoable edit. Snapshot validation rejects unknown tempo with Warp enabled; the command boundary also rejects that combination. The content codec retains the marker for Arrangement and Session, while backend projection excludes it. Legacy clips without the marker keep their saved interpretation.

`shared/app-shared/audio-import-preferences.ts` owns the application-wide, localStorage-backed `AudioImportPreferences { autoWarp }` (default on), separate from project documents and undo. Both picker and Browser imports capture this preference before asynchronous work. Off skips tempo analysis and imports original duration and speed. On uses bounded native analysis and enables Warp only for a valid source BPM. New imports use the Signalsmith mode. Unknown or failed analysis keeps original speed and shows a notice; it does not change the project BPM. Import remains one undoable transaction.

Native tempo analysis treats autocorrelation support as evidence of periodicity, not proof of the beat unit. If selected onsets strongly fit a triplet subdivision but do not support the candidate's straight subdivision, the result remains unknown. The phase histogram reuses bounded stack storage, does not read tempo from filenames and does not choose a half, double or three-to-two correction. This can reject unannotated swing or triplet material; trusted tempo metadata retains precedence. First-beat alignment, variable-tempo maps and broad music accuracy remain outside this guard. Measured source identities and limits are recorded in [tempo evaluation](../../../../../../docs/research/warp-tempo-options-2026-10-25.md#2026-10-27-metrical-ambiguity-guard).

Browser drags share one typed transient session with an opaque DataTransfer token, outside authored project state. Known duration comes from measured Preview metadata. Unknown duration has no guessed musical width or waveform. Arrangement previews use the shared grid, scroll and track geometry. `@zoeydaw/project-core/audio-drop` shares target eligibility between geometry and import. Audio and instrumentless MIDI lanes accept audio. The current Device union contains effects only. Dropping on MIDI switches the same track to Audio, replaces its MIDI/Pattern clips with the imported audio, keeps identity, mixer and effects, and routes to its valid group parent or Main with Audio input/channel defaults. This is one document transaction. Undo restores the original track, contents, routing and media. Pinned buses, Group rows, automation sublanes, rulers and headers reject audio. The trailing empty area previews a new composite Audio row, its right-hand header controls and the clip ghost without changing authored state or history. Drop creates the track and clears drag ownership while the import preview remains until handoff. Escape, blur and unmount cancel an active drag. Dragend clears drag ownership without discarding a pending import preview. Arrangement and AudioEditor consume derived waveform ranges, including PCM at sample-level zoom, outside the editable document.

Browser placement and formal Clip presentation share `paintClip`; the preview variant uses half-opacity track-colored Header and real waveform with a transparent body, without selected/hover highlight. Preview waveform metadata and ranges stay in an independent demand owner after Browser drag ownership clears. Pending import captures source and musical placement, reprojects for viewport changes, then waits for the formal source's own ranges while they are pending. Formal reads require the exact source ID, SHA-256 and locator key. Path-only Browser ranges are never promoted or relabeled as fingerprinted content, even when frame count, sample rate and channels match. Failed range loading still permits handoff to the actual painted Clip. Native waveform data remains derived cache, outside authored project state.

## Snapshots and source data

`serializeProject()` returns version-5 JSON containing committed `document`, including `document.media`, shared `document.patterns`, Session scenes and sparse slots, and `workspace` only. Temporary numeric edits, Canvas previews and observed launcher state do not enter saves. `hydrateProject(json)` validates and clones the complete payload before replacing state and resetting session/history. Invalid references, duplicate identities or invalid note content leave the current project intact. Versions 1–4 migrate to an empty Session. Version-1 and version-2 audio paths migrate only empty and `mock://` sources. Versions 1–3 migrate boolean Pattern steps into C4 notes at velocity 100, preserving step timing and separating conflicting legacy Pattern identities. Native storage accepts v5 and validates Session-only media references during Save and Collect.

Toolbar Save and Cmd/Ctrl+S call the asynchronous `projectFiles` facade, not `projectActions`. Normal Save writes a `.zdaw` JSON manifest and preserves external source references. Save As and Collect copy verified media into `media/<uuid>.<verified-extension>` before publishing the manifest. Save As keeps project identity and changes its file binding. Each publication uses a fresh commit ID and checks the expected prior commit. localStorage stores only recent project locators, not project contents.

`captureProjectSave()` captures committed document/workspace and the editing epoch, revision and rejection generation. `waitForProjectSave(capture, signal)` accepts later acknowledgements that include the capture, rejects cancelled or invalidated captures, and does not wait for an exact latest revision. `completeProjectSave(capture)` never marks newer edits clean. A published manifest with uncertain directory durability updates the binding but leaves the project dirty.

After the captured revision is accepted, Save requests a complete state snapshot from every running external Device. `plugin_device_snapshot` enforces window/session ownership and uses the existing control worker and content-addressed state store. Only state references cross IPC. Unchanged hashes reuse collected bindings; new chunks enter the saved manifest without mutating the editable document. Snapshot failure, cancellation or edits during capture prevent disk publication. This is a save checkpoint, not a simultaneous sample-atomic snapshot across plugins.

Before capturing a save revision, `projectFiles` waits for open plugin editors to close and commit their state. Otherwise a live chunk could be paired with older committed parameter overrides. `plugin-editor/` owns the single-flight 100ms notification poll and editor-session edit token. Native parameter values update the existing document; opaque dirty notifications keep the unsaved guard active. Closing the helper window or choosing Close and Apply captures its complete chunk and ends one undo entry. Overflow requeries metadata and values. Stale project/edit ownership cancels the editor and restores its native checkpoint instead of writing into another edit. Unsupported editors and failed captures report their real errors.

`plugin_device_editor` checks the window-owned session, expected catalog and state hash before opening. Later requests require the exact control-worker instance. Native manual feedback is suspended only for that prepared processor; track automation remains active. Closing restores authored manual authority. A new chunk uses the existing preparation path, while ordinary editor parameter notifications retain the running helper. The Windows helper smoke verifies a real CLAP window, ordered gesture/value notifications, edited chunk reload and native checkpoint rollback. Browser interaction uses an explicit mock transport. Tauri editor interaction, physical audio and VST3 editor acceptance remain separate desktop checks.

Plugin health is sampled by the existing control workers during the low-rate status poll, outside the registry lock and audio callback. `pluginFaults` contains only currently faulty instances and is fenced by window, lease and session. Supervisor exits report crashes. A hang requires at least two seconds without completion of pending SDK audio, so idle endpoints are not classified as hung. Callback contract failures require reprepare. Incidents enter the existing acknowledged realtime EventLog once per identity; gaps carry the current latched faults and real incident count. Healthy snapshots and resource removal clear current faults, not historical event sequences.

Explicit recovery cancels the affected native editor transaction, waits for authored backend updates, and requests the actual native owner's checkpoint and parameters. `recover_realtime_configured` applies those values to the fresh candidate and verifies the retained graph's latency before publishing its ring. It preserves the Edit and callback endpoint, advances helper identity only after success, and republishes the latest native manual values. Stale replies cannot clear newer faults or another project's state. Recovery restores the checkpoint, not unsaved plugin-internal edits or DSP history. Candidate failure stays in the existing fallback and reports its real error; nothing retries automatically. A prepared helper is not a document audio-adoption acknowledgement.

Recovery is single-flight per session and Device across views and helper generations. Parameter and editor controls stay excluded until that operation finishes. Editor commands recheck their instance inside the worker, and native manual authority rejects older instance tokens. A late cancel, release or event poll therefore cannot close, roll back or drain the recovered instance's newer editor.

Open prepares and validates the candidate before `replaceProject(seed, signal)` installs it. Backend rejection, cancellation or intervening edits preserve the current project and history. Unsaved navigation uses Save, Discard or Cancel. Missing, changed and unreadable sources remain explicit issues. Relink requires the original fingerprint and audio dimensions, retains `sourceId`, and does not silently accept a same-named replacement. The native worker hashes and copies bounded buffers; no PCM crosses WebView IPC. Native storage tests do not prove audible playback or Windows runtime compatibility.

App-global `ApplicationLifecycle` owns the unsaved dialog and the native close handshake. OS close, TitleBar and explicit process exit use a pending native ticket. Native refuses exit until `resolve_app_close` authorizes that ticket once. Hiding to tray preserves the window and project owner. Quit waits for Save, Discard or Cancel; failed, cancelled or uncertain saves keep the app open. Active file operations block Quit visibly. Gallery never bypasses dirty confirmation and cannot save fixture media. Forced process termination is outside this protocol.

Native import decodes every packet with bounded buffers and checks actual frame counts for lossless containers. Truncated, empty and unsupported audio is rejected before registration. Relink issues are projected against the effective current locator, so undo restores a known missing-source issue rather than silently hiding it.

Restore requires exactly one Main output with ID `main`. Audio tracks own audio clips; MIDI tracks own MIDI or Pattern clips. Group, Return and Main cannot own clips. Commands and snapshot validation share `acceptsClip`.

Pattern cards reference `document.patterns` through `patternId`. Each shared entry owns MIDI notes and loop length; cards retain independent placement, trim, mute and appearance. The existing piano roll edits shared content through document history, so every reference updates and undo/cancel restores them together. Canvas and MiniMap resolve the same notes. Clipboard payloads carry referenced content, reuse matching identities and remap conflicts without overwriting destination music. Backend projection resolves Pattern cards into the same MIDI DTO and native scheduling path as MIDI clips; boolean-step rendering and backend paths have been removed.

Every project retains at least one ordinary Audio or MIDI track; Main, Return and Group do not count. A direct, multiselected or recursive Group deletion that would remove the final ordinary track is rejected atomically: document, selection, history and backend state stay unchanged. Undo/redo restore valid authored snapshots. Snapshot parsing validates and clones bus-only version-1/2/3 data without depending on UI measurements; runtime hydration and replacement then add one empty Audio track using the shared default height, before backend opening, without replacing buses, routing, media, markers or workspace data. Invalid snapshots still fail validation before normalization.

Audio `waveformPeaks` are derived visual data and are omitted from snapshots and engine DTOs. Only media records with `location.kind === "fixture"` regenerate demo previews. Real sources and empty clips display no generated waveform. Clip trim/split retains the stable source identity and changes `sourceOffsetBars`; MIDI notes, Pattern phase and preview share that window. Fade duration, offset, curve and midpoint fields remain saved metadata with the existing interval constraints.

Real waveform ranges use `framesPerBin`, a source-zero-aligned power of two. B=1 returns at most 8192 raw frames; B>1 returns signed extrema for exact B-frame bins, including the final partial bin. Requests are bounded to 4096 bins and raw interpolation includes 32 samples of support on each side. Arrangement, Audio Editor and Browser share the demand scheduler, which owns the one active native range request and its cancellation. Browser first requests one raw frame for source metadata, then replaces its demand with the width-dependent binary ranges.

`playback_waveform_range` returns an `ArrayBuffer` through Tauri `ipc::Response`. The authoritative header is `protocol/waveform-range.json`, generated with the existing realtime protocol generator. Its 64-byte little-endian header identifies the version, kind, sample rate, source range, channel count, bin size and exact payload length. Payloads contain channel-major float32 planes: samples, or minimum then maximum per channel. The maximum payload is 2 MiB, excluding the header. C++ writes directly into the caller's Rust-owned buffer through a synchronous allocation callback; errors reject the command and discard any partial buffer. There is no successful JSON range response or compatibility fallback. Overview responses remain JSON.

`decodeWaveformRange` validates the binary boundary against the originating request, including exact EOF clamping, safe frame counters, finite samples and ordered extrema. It materializes the existing numeric arrays once for the shared Web cache and Canvas consumers. This removes native JSON arrays and Rust JSON parsing, not all IPC copies or the Web numeric-array allocation.

Native analysis keeps immutable `WaveformData` ranges in a process-local LRU cache with 64-entry and 32 MiB float-payload limits. An exact request shares its retained arrays; a covered coarser request reduces raw samples or finer extrema into exact min/max bins. Finer requests never expand coarse data, and a partial cached bin is reused only when the requested end matches that cached boundary. Decode and reduction remain in the existing range path. Cache lookup/publication use a short mutex; decoding, binary encoding and reduction run outside it. In-flight readers can retain evicted arrays, so the cache limit is not a whole-process peak-memory guarantee.

Native cache identity uses the full path, OS file identifier, byte size and last-modification time. Changed identities invalidate retained ranges for that path, and a change observed during processing rejects the response. This detects normal file replacement and modified files, not same-size writes that deliberately preserve all identity metadata. It does not recompute SHA-256 on every request or verify the current file against the project's stored hash. The Web cache continues to use source ID, SHA-256 and locator; the range request fields remain unchanged.

Tauri injects the originating `WebviewWindow` into overview, range and range-cancel commands. `PlaybackService` owns separate cancellation epochs for each window and job family. Jobs retain the existing epoch and its expected value rather than allocating a cancellation object per request. A new range supersedes only that window's previous range; explicit range cancellation leaves overview work intact. Window destruction cancels both families and rejects late jobs for that closed owner. The job retains its ticket through the synchronous native callback, including when the service is dropped. Native decoding checks cancellation before opening the source, between decode blocks and before building the response. No process-global waveform generation or fence API remains.

The range cache targets 64 entries and 32 MiB of numeric payload, counting each shared `WaveformRange` once at eight bytes per number. It evicts the oldest unused ranges on completion, demand changes and final consumer release. Active demands stay pinned and may temporarily exceed these targets. The budget excludes JS object overhead; it does not copy PCM, impose a whole-process heap limit or change the native range protocol.

`signed-waveform.ts` follows the inspected Live Arrangement algorithm. Above one sample per logical pixel, adjacent binary peak layers morph both x positions and extrema by the fractional part of log2(samplesPerPixel). At one sample per pixel or closer, `waveform-interpolation.ts` reconstructs normalized 65-tap Lanczos32 phases, capped at 128 subdivisions per sample. Original samples receive 2×2 markers from 8 logical pixels per sample. `waveform-polygon.ts` expands the upper-forward/lower-reverse contour by half a pixel and quantizes vertices to 1/256 pixel before one fill. Consumers do not add an independent stroke. Browser and editor use the same geometry; their separate native Live entry paths have not been inspected. JS FMA rounding and Web raster coverage are not claimed bit-for-bit identical to Live's runtime backend.

Arrangement rasterizes only its visible source slice at the display backing resolution. Reverse, loop seams, clip gain and fades use source-time projection; fade intervals include the original-speed rate when Warp is off, and completed fade-out remains silent. Cached range identity participates in bitmap invalidation. Native waveform ABI changes require a rebuild; the Agent maintains `tauri:dev` and verifies that the application recovers.

Tracktion's `AudioFadeCurve::Type` offers four fixed shapes, not this two-axis control, so the existing native Envelope applies the matching gain directly to the current audio block without an extra audio buffer or Web round trip. Same-track audio placement edits call `AudioClipBase::setPosition`; the envelope's source window and fade fields publish together through the existing snapshot. Native regressions cover draggable anchor gains, move/trim/source-offset behavior and undo. Web tests cover curve geometry and editing; desktop drag verification is separate.

Audio edits match clips by stable ID, not array position: Web move operations remove and append clips, so array order may change without replacing native objects. Changing the content or availability of an existing clip's source, track conversion and device automation remain separate incremental-integration work.

Transpose, detune, Warp, source BPM and mode edits update the existing native clip's speed/pitch settings, preserving transport and custom fades. Start/End edits update the source window without changing authored Arrangement geometry. Clip-local Loop uses native `setLoopRange` and `setPosition`, independently of the project loop. Stepped-source renders at 120/180 BPM verify edited loop content and repetition. Current modes use SoundTouch, Signalsmith, Signalsmith Formant and Re-pitch, not Ableton's named algorithms. These are pre-device observations, not desktop latency measurements.

`AudioClipSettings.warpMarkers` optionally stores up to 256 stable-ID `{ sourceBar, targetBar }` pairs in zero-based source-tempo bar units. The Audio editor shows transient candidates derived from the existing 4096-bin native source overview. Source and target coordinates remain bounded by the existing segment-ratio rules. Native uses the existing Clip WarpTimeManager; waveform and source-position projections use the same marker map. Physical click-free marker editing and Live-equivalent analysis are not established.

Reverse uses native `setIsReversed`, followed by the authored loop and offset setters so Tracktion's automatic loop-point reversal does not override the UI's source coordinates. Arrangement observes native render-job completion and holds the existing `ReallocationInhibitor` while required source renders are pending, preventing readers from opening incomplete files. Cancelled/deleted clip renders lose their listener and graph hold; completion only updates graphs still using that file. Other channel layouts are not implicitly widened. External audio inputs bind only to enabled device channels. Document edits do not request microphone permission or open an input device. ## Timeline geometry

`@zoeydaw/project-core/selectors` derives the document's timeline extent from every clip end, marker, loop boundary, and automation point. The minimum view is 128 bars, with 16-bar rounding and trailing editing room. The viewport controller also accommodates the current playhead and time selection. Extent is derived data and does not enter snapshots.

`../sections/ArrangementPanel/Timeline/Viewport/useTimelineViewport.ts` shares measured zoom and logical scroll with MiniMap and both rulers. `TimelineCanvas.tsx` composes the viewport, toolbar, painters, headers and editors. `canvas/layout.ts` supplies row positions to painting, hit testing and headers. Normal tracks scroll together; Return and Main stay above the bottom ruler. MiniMap retains source Clips when groups fold. Its percentage-based frame maps logical musical bars, not a document-wide DOM canvas or physical scrollbar. Extreme zoom and far-bar navigation still allocate only the visible canvas size.

`workspace.grid` stores adaptive density or explicit fixed bars, plus an optional triplet flag. `deriveGridPlan()` projects preference, zoom and meter into `scene.gridPlan`; drawing and snapping share the same triplet-adjusted `cellBars`. Ctrl/Cmd+1 and +2 change density, +3 toggles triplets, +4 toggles snapping, and +5 switches fixed/adaptive mode at the current cell size. Grid shortcuts belong to Arrangement focus and do not intercept Browser input, Clip editors, menus or Dock tabs. Older version-2 snapshots omit triplet; malformed flags are rejected. Numbered ruler ticks remain independent from the edit grid, as does background shading.

The loop brace remains visible and editable while transport looping is disabled. Clicking its body selects the loop interval across every document track, including groups, folded children, Return and Main, without enabling playback looping. Its muted/primary appearance distinguishes disabled/enabled transport state; geometry does not depend on that state.

The MiniMap frame resizes independently from either edge, pinning the opposite musical boundary. Body dragging pans horizontally and zooms vertically around the pressed position. Clicking outside centers the frame; double-click fits the project. Browser Pointer Lock supplies relative motion. Native dragging hides and confines the cursor, recenters it near window edges and discards the resulting synthetic movement. Release waits for the pending recenter, restores the pressed fraction of the current frame and reveals the cursor. A pending release prevents another drag. Escape, blur, cancellation and unmount release the cursor and retain the last valid viewport.

The overview spans the full Arrangement width without a separate debug area. It retains Group and empty source-track rows, including children of folded groups, and excludes Return and Main. Solid Clip bands, row dividers, locators and the transport position use the same bar coordinates. Semantic `--arrangement-overview-*` tokens in `project.css` inherit the shared theme and distinguish these elements without brightening the timeline grid. Canvas and DOM share those tokens.

The overview height uses the shared resizable `Group`, `Panel`, and `PanelDivider`. Its default and minimum are 32px, its maximum is 90px, and the timeline retains at least 160px. The separator supports pointer dragging and keyboard resizing without starting a MiniMap navigation gesture.

Canvas backing-store resize and repaint occur synchronously in `ResizeObserver` for the scene, playhead, and track meters. Unchanged pixel dimensions do not reset the backing store. The shared scheduler still coalesces ordinary state changes.

Clip titles select cards, set their playback origin to the Clip start, and initiate movement. Only title-height left/right edges resize the card. Body edges retain fade handles and time selection. Audio left extension clamps to source zero while moving and commits the same boundary on release. Movement, resize, Fade, Loop and Locator gestures retain their last valid preview on capture interruption. Escape cancels. See the [rendering architecture](../../../../../../docs/architecture/rendering.md) for Canvas projection and the native telemetry boundary.

The insertion point is independent from moving transport position. Space starts from that anchor. Its track-local line and ruler marker remain visible during playback, breathing between theme colors with a 1200ms triangle pulse; the full-height transport line moves independently. `paintClipAlignment` independently adds a neutral full-height editing guide, at the Ghost's left edge during movement or the grabbed edge during resizing. It does not seek or replace playback. Resizing commits its playback origin at the Clip's left start, regardless of the grabbed edge. Telemetry never overwrites the insertion point.

Range clipboard operations use `timeSelection.trackIds` and `[startBar,endBar)` even without selected Clip IDs. The optional `ClipClipboard.range` stores `lengthBars` and `trackCount`, preserving leading/trailing silence and ordinary-track offsets through empty lanes. Delete/cut retain outside Clip fragments and source phase. Paste uses the current range/insertion anchor and replaces the entire destination interval, including copied gaps, in one undo transaction. Group rows do not occupy clipboard lane offsets; Audio/MIDI child tracks do.

Space is claimed before focused buttons and menus in capture phase; native keydown/keyup activation is suppressed, repeat does not toggle transport twice, and focus is released from non-editable controls. Text fields, contenteditable, IME, modifiers and Enter retain their existing behavior.

Normal card activation and rename update selection/focus without opening Clip View. Creating a Clip from an empty lane or the lane menu selects it and opens Clip View, matching the observed Live behavior. `session.editingClipId` retains a single Clip editor focus through undo; `session.clipEditorRequest` separately signals explicit Open Clip View or close requests. Footer derives none/multiple/single selection and dispatches a single editor by kind. Clip and Device visibility belong to the shell, not document/history, and neither acquires another backend. The old 190px editor embedded in Timeline is removed.

Audio `audioSettings` stores independent playback Start/End markers (`startMarkerBars`/`endMarkerBars`), independent source-loop position/length, warp mode/source BPM, pitch metadata and reverse/loop flags. Start/End markers edit only this metadata; they never move, trim, or resize the Arrangement Clip's `startBar`, `lengthBars`, `sourceOffsetBars`, or its fades. Musical positions format as one-based bars.beats.sixteenths using the clip's actual numerator/denominator (sixteenths-per-beat = 16/denominator, so a 4/8 meter has 2 sixteenths per beat); durations are zero-based. MIDI retains complete source notes across the full 0–127 pitch range; viewport/Fold/zoom/selection stay local, and pointer edits use the existing session-fenced transaction. Shared held-B and computer-keyboard releases remain globally owned.

Track `devices` is an optional ordered, typed chain of Utility, Filter, Delay and Reverb metadata. Add/remove/order/bypass/fold/parameter edits use public track commands and normal history; validation rejects malformed values or duplicate IDs within a chain. Snapshots roundtrip both device and Audio settings. These fields describe Web prototype authoring only: the engine DTO still excludes device DSP, warp/pitch/reverse processing, PCM and media-file loading.

`canvas/clip-geometry.ts` supplies shared painting and hit geometry. `../layout` derives `TRACK_LAYOUT`, collapsed/title heights, resize steps, control-column width and row capacity from the public `@zoeymind/ui/metrics` configuration. Its CSS counterpart is generated from the same JSON and drift-checked. Timeline maps that layout to scoped variables; DOM, Canvas and hit testing share the result. Domain timeline-extent selectors remain in model. Routing progressively reveals rows that fit; folded tracks expose no body or Automation targets.

Ordinary tracks resize from their bottom boundary. Return and Main tracks resize from their top boundary, so downward motion shrinks them toward the fixed bottom edge and upward motion expands them. Keyboard arrows follow the same directions. Track seams have one bottom-edge owner rather than doubled adjacent top/bottom borders.

`canvas/interactions/controller.ts` owns pointer capture, drag threshold, clipboard routing and autoscroll. Each autoscroll frame recomputes the preview from the current viewport. Automation mode preserves Clip-title movement while bodies edit automation. Keyboard commands in that mode do not operate on a hidden Clip selection. When Clips move in Automation mode, their interval's breakpoints move through the shared `model/clip-automation.ts` projection in both preview and commit.

Clip clipboard payloads are versioned and parsed at the input boundary. Copy, cut, paste and duplicate preserve source windows and relative lane/bar offsets while assigning new clip IDs. Clip, automation and MIDI-note clipboard codecs share one raw-text mirror; unrelated pasted text cannot revive an older clip payload. Text inputs and MIDI editors retain their native clipboard events.

Locators support snapped movement, Shift snap bypass, rename, delete and navigation. Double-click starts playback from a locator without stopping an already-running transport. Arrow keys move the selected locator rather than seeking. Loop body movement preserves length; either edge resizes independently, and Cmd/Ctrl+L creates a loop from the selected time range.

Automation uses a normalized envelope with optional per-segment curvature and a typed target: mixer volume/pan or a specific device ID and valid parameter. The two-level selector offers None, a signal-capable track mixer, and real devices; None disables the parameter selector. Choosing a target creates no authored envelope until editing begins. Device numeric editing accepts its actual units, including Hz, milliseconds and percentages. The painter and simulated meters share `model/automation-curve.ts`; no device DSP is implied.

`workspace.automationLanes` owns additional displayed target rows; `session.automationTargets` owns the main-row selection; document envelopes own points. Extra rows share geometry between Canvas, hit testing and header layout, including pinned Return/Main. Hiding a row, folding its track or disabling Automation preserves envelopes and display choices. Deleting its device removes the now-invalid envelope and display target in the same undoable edit. Track duplication remaps device identities. Snapshot input migrates old volume/pan envelopes to typed mixer targets and rejects invalid device references. Point/segment gestures retain preview, cancellation and undo behavior.

`workspace.arrangementView` owns independent routing, Return and overview visibility. These are view preferences with normal workspace history, not document edits. One projection supplies visible tracks and the header/Canvas/minimap control width, so hiding routing removes the whole column and hiding Returns removes their headers, lanes and automation rows while Main remains bottom-anchored and authored tracks, sends and selections survive. Hiding the overview removes its panel, divider and reserved height; the time viewport reflows to the recovered safe height.

The Arrangement lower-right label shows the effective grid, including when Automation is off. Adaptive Narrowest reaches `1/16384` notes at maximum zoom with an 8px cell in both 4/4 and 4/8. For meter `n/d`, a `1/N` note occupies `d / (n * N)` bars. All viewport and MiniMap zoom paths share the limit, while logical scroll can exceed 16 million pixels without allocating an equally large canvas. The ruler adds readable bar, beat and sixteenth labels independently of the finest grid. Clip duration floors and Float64 simulated playhead storage preserve fine positions at distant bars.

## Track control states

`session.selectedTrackIds` identifies active tracks; `session.trackSelectionSurface` distinguishes Arrangement focus from header focus. Lane, Clip and automation clicks mark Arrangement focus: the row is highlighted but no right-side identity, routing or mixer area is highlighted. Header clicks mark header focus: only the colored name/identity area uses the shared selection tint, while routing and mixer controls keep their normal appearance. There is no selection border, shadow or whole-header overlay. Clicking a lane clears any previous identity tint, including when the same track remains active. `useSceneSync` projects active IDs for row drawing; header selection does not seek the insertion point. Focus and selection remain transient and are not saved.

The track-selection command requires an explicit surface, so a new input path cannot silently reuse header-focus styling for an Arrangement click.

| Main | Cue output, main output, main level, headphone-marked cue level and pan; no activation, Solo or arm | Both output rows, main/cue levels and pan | Main output, main level, cue level and meter |

Internal destinations leave the secondary output row blank and disabled. Return self-send is displayed disabled to prevent feedback. Input/output channels, cue output/level, per-return sends and Pre/Post are document state and survive snapshot roundtrips. Old Audio input channel IDs migrate to the external input route plus a separate channel at the snapshot boundary. These controls edit the Web prototype; they do not imply a connected audio engine or hardware routing.

`trackControlRows` derives control capacity from the same row-height unit as resizing. Routing progressively restores input and secondary-output rows as height increases. Send controls render only when they fit, so hidden rows cannot retain keyboard focus outside their track. The state smoke captures full, short and collapsed states for all five track kinds.

Group's arm slot is empty and non-interactive; its activation width matches Audio and MIDI rather than expanding into that slot. Track meters share the compact-control width and read linear stereo samples from MeterStore, converting them to dBFS for display. The Canvas painter shows −60 to +6 dB, a 0 dB line, a green-to-yellow gradient below unity, and red overload above unity. Per-channel peak markers hold for 600ms and then fall at 24 dB/s, including after playback stops. Peak state is local to each meter and never serialized.
