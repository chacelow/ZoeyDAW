# 先复用已有能力

由当前主 Agent 顺序执行，只调查与当前需求有关的能力。不把普通代码阅读、纯业务调试或机械重构扩展成全栈升级调研。

1. 读取实际调用链、manifest 和锁定版本源码，寻找项目已有组件、模块和平台 API。确认当前缺口，避免只因名称不同重复实现。
2. 对库、框架、SDK 的 API、配置、版本迁移或能力问题，使用当前 Context7 工具查询官方说明。先读取工具 schema，按实际可用参数调用：
   - `xd://mcp__context7_resolve_library_id`
   - `xd://mcp__context7_query_docs`
3. 官方文档描述新版本时，与项目锁定版本区分。当前运行行为以锁定源码和实际输出为准，不能把尚未升级的 API 当作已经可用。
4. Context7 不可用或覆盖不足时，说明限制并查官方源码或一手文档；不要因单一工具失败停止可完成的工作，也不凭记忆虚构 API。
5. 现有技术栈确无合适能力时，再比较外部方案的接口、依赖、许可及迁移成本。新增 npm 依赖、共享 UI 公共 API 和发布动作仍遵守项目授权。
6. 给出具体判断：复用哪个现有接口、为何满足当前需求；或缺少什么行为、最小新增实现是什么。研究结果不等于运行验证。

清理与当前需求无关的旧代码或切换音频、状态、同步后端，不属于本 Skill 的自动授权范围。
